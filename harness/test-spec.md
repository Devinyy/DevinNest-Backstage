# 验证规范与覆盖边界

## 先判定验收方式

先按[验收方式判定](scenes/verify.md#验收方式判定)确定是否必须独立 QA，再选择下列检查。lint、build 或执行角色自测通过，不替代命中条件后的独立验收；无环境时记录受阻与未覆盖范围。

## 自动检查

在项目根目录使用 Node.js 20：

| 检查 | 命令 | 覆盖 |
| --- | --- | --- |
| 依赖复现 | `npm ci` | 需要安装依赖时按锁文件安装 |
| 静态规则 | `npm run lint` | ESLint |
| 类型与构建 | `npm run build` | `tsc -b` + Vite 生产构建 |
| 产物预览 | `npm run preview` | 人工检查已构建页面，不自动判定业务通过 |

目前 `package.json` 没有 `test` 脚本，未发现已纳入版本管理的自动化测试用例。不得声称单元 / 端到端测试已通过。检查失败应记录是否与本次变更相关，不通过禁用规则掩盖问题。

## 按变更选择验证

- 文档：检查差异格式、相对链接、MAP 可达性和事实来源；无需运行业务构建。
- 前端逻辑：lint、build，加受影响页面操作及错误路径；涉及 API 的验证需要真实或明确标记的模拟环境。
- UI：在可运行页面检查受影响尺寸、加载 / 空 / 错误状态、键盘与焦点；没有运行环境须明确未验证部分。
- 发布配置：核对构建命令、输出目录、环境变量、SPA 路由；没有发布授权时不推送 `main` 或执行部署。

## 人工冒烟

按影响选取：未登录路由跳转、登录 / 退出、仪表盘、博客 / 碎片列表、新建与编辑保存、图片上传、深层路由刷新。创建或删除真实数据前核对环境与任务授权。

## 证据

报告记录分支 / 提交、检查命令或操作、实际结果、未覆盖范围；截图与日志通过路径引用。独立 QA 流程见 [验收场景](scenes/verify.md)。
