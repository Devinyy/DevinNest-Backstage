# 开发与修复场景

1. 检查工作区和当前分支，保护现有改动；明确本次目标、影响和完成条件。
2. 从 [实现地图](../impl.md) 定位模块；需求不明时只读取 [需求地图](../../requirements/MAP.md) 对应资料，关键歧义才询问。
3. 新文件或改名读 [命名规范](../naming.md)；UI 任务读 [设计地图](../../design/MAP.md)；API 任务只读 API 文档对应模块与调用代码。
4. 按任务复杂度决定是否需要原型或技术方案；涉及架构和公共能力的权衡写入 ADR。
5. 在授权范围内实现，按 [验证规范](../test-spec.md) 自检；普通问题由当前执行角色修复并复验。
6. 更新受影响的实现事实、偏差和最近一层 MAP，交付结果与验证证据。没有明确授权不推送生产分支。

这是阅读与执行入口，不要求每个任务建立多代理流水线。独立且并行收益明确时才拆分，代理间通过资料路径和摘要共享上下文。
