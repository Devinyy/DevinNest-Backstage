## ADR-001：以 Cloudflare Pages 为当前生产发布入口

- 状态：现状确认（2026-11-06），不是本次新增基础设施。
- 证据：用户提供的 Cloudflare 项目及构建配置截图；配置摘要已记录于 [README](../README.md#-部署指南)。
- 选择：GitHub 仓库的 `main` 自动构建 `dist` 并发布；Docker 配置保留作备用。
- 影响：日常发布不运行 `deploy.sh`；生产 API 地址在构建时注入；改动进入 `main` 即可能触发生产发布。
- 未知：原始选型动机未提供，不补写；用户先前认为无分支预览，但 PR #11 的 Cloudflare 检查已成功创建当前功能分支预览；仍待核对项见 [偏差记录](deviations.md)。
- 2026-11-06 用户补充：正式域名和 API 变量来源已确认并记录在 README；旧 Docker 服务仍在使用、可能停止更新。原“保留作备用”的描述不代表旧实例已具备同步版本或可用性保证。

## ADR-002：使用 MAP 渐进读取项目文档

- 状态：按用户 2026-11-06 的请求建立。
- 背景：需要让代理按任务获取上下文，避免把全部规范塞进入口。
- 选择：根 AGENTS 定义权威层级、场景路由和契约，各目录 MAP 指向专项文档；既有 API、发布资料保留原位置。
- 代价：新增或移动文档需维护最近一层 MAP 和相关引用。

## ADR-003：以当前代码建立需求与设计基线

- 状态：用户已确认（2026-11-06）。
- 证据：针对是否以代码为基线整理需求与设计的询问，用户回复“先以当前代码为基线”。
- 选择：根据当前源码记录模块行为、字段、样式与交互，保留未完成功能和待确认项。
- 边界：不将未知的业务规则补写为事实，不将静态核对写成运行验收；此确认不授权开发缺失功能或发布。
- 维护：实现变化同步对应模块与样式文档；后续提供 PRD / 设计稿时核对差异并记录决策，不静默覆盖证据。
