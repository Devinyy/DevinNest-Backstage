# 已确认业务规则

仅记录用户明确确认的目标行为，按编号引用；代码现状仍见模块文档。确认规则不代表已开发、已验收或授权本轮修改业务代码。

## SN-001：碎片禁止发布空内容块

- 来源：用户于 2026-11-06 选择“禁止空块：文本/引用须有内容，图片须有图，图集至少一张”。
- 目标：发布时除了标题非空、至少一个块，每个 text / quote 块须有内容，image 块须有图片，gallery 块至少一张图片；不符合时应阻止发布并指出问题块。
- 现状：前端只检查标题和块数量，没有逐块内容校验；已核对本地后端 schema 与保存接口，同样未见逐类型非空校验。
- 状态：规则已确认，前后端待实现，线上状态未验证；不能将旧的宽松校验当成目标验收标准。

## SN-002：新标签进入碎片公共标签库

- 来源：用户于 2026-11-06 明确“应该属于碎片的公共标签库”。
- 目标：碎片发布使用的新标签名应归入碎片公共标签库，供其他碎片复用；不能据此推断博客也应自动共享这些新标签。
- 现状：博客与碎片编辑器都调用同一个 getTags()，碎片提交名称数组；前端没有明确的标签域参数或专属列表接口。
- 状态：归属已确认，本地后端已确认共用 tags 表，按名称查找或自动创建，没有业务域隔离，尚不满足此目标。物理表设计与接口调整未决定，不擅自新增。

## TX-001：分类和标签的删除保护

- 来源：用户于 2026-11-06 确认采用建议。
- 目标：有内容引用时禁止直接删除，提示先迁移或解除关联；无引用时允许删除，并要求二次确认。始终保留博客和碎片内容，不级联删除内容。
- 现状：首页删除直接发请求，没有二次确认；已核对的后端删除接口直接 db.delete，未见删除前业务引用检查；未在 taxonomy 路由发现专用迁移 / 解绑接口。
- 状态：规则已确认，前后端待实现，数据库实际删除效果未验证。前端显示的 count 不足以证明删除瞬间没有引用，引用约束需由后端保证。

## TX-002：同库禁止重名

- 来源：用户于 2026-11-06 确认同库禁止重名，并确认去掉名称两端空格、忽略英文字母大小写后比较。
- 目标：各自的分类库或标签库内禁止重名；博客标签与碎片标签允许同名，不因此合并或共享标签归属。新增及改名均应遵守。
- 现状：前端名称表单只做必填与提交状态检查，未见重名检查；本地后端模型 name 有 unique=True，创建 / 更新按原始名称等值查询，未见显式 trim / lower；没有标签业务域。
- 比较规则：先去掉名称两端空格，再忽略英文字母大小写；React、react 和“ React ”视为同名。此规则也适用于碎片发布中新标签的复用与去重。全半角转换等其他等价规则不在本次确认范围内。
- 状态：规则已确认，前端待实现、本地后端比较及标签域隔离尚不满足目标，数据库排序规则与线上约束未验证。

## ED-001：仅有未保存改动时提醒离开

- 来源：用户于 2026-11-06 明确“需要，有未保存改动才提示”。
- 目标：博客 / 碎片有未保存改动时，返回、切换页面或关闭页面应提示；用户取消则保留当前编辑，确认则离开。无改动、编辑详情初始化回填、成功保存后的正常跳转不应误报。
- 范围：应覆盖编辑字段、封面、正文与内容块（含增删、内容修改和排序）。仅上传文件成功不等于整篇内容已保存。
- 现状：未发现编辑脏状态跟踪或离开拦截。
- 状态：规则已确认，前端待实现；关闭 / 刷新使用浏览器原生离页提示，能否展示受浏览器限制，不承诺自定义文案或任何退出情形都可拦截。

## SC-001：当前不需要草稿功能

- 来源：用户于 2026-11-06 明确“目前不需要，保留现状记录”。
- 范围：博客和碎片草稿均不列为当前待开发需求；保留按钮仅提示“暂未开放”的现状记录，不因按钮存在而自行安排开发。
- 状态：范围已确认；本轮不修改、隐藏或删除现有按钮。不影响已确认的 ED-001 离页提醒需求。

## UI-001：电脑为主，手机能完成主要操作

- 来源：用户于 2026-11-06 选择“电脑为主，手机能完成主要操作”。
- 目标：电脑为主要使用与验收端，手机需能完成主要操作；不是仅展示可读，也不推定要求所有设备具有完全相同布局。
- 现状：部分页面具备响应式网格，主布局固定侧栏和首页固定栅格的手机可用性尚未验收。
- 手机范围：用户进一步明确“只需要登录和查看、编辑”。手机端验收限登录、查看首页 / 列表 / 内容、编辑已有博客 / 碎片并保存；新建、删除、分类 / 标签管理不列入当前手机必需范围。
- 状态：设备目标及手机操作范围已确认，实际适配效果待验证。
